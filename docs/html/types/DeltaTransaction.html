    receivedAmount

    receivedAmount: string | null

    Description

    Which leg this reports depends on the order: the destination leg for bridge fills, the origin leg otherwise. Unlike destinationReceivedAmount it is not gated on the bridge having filled, so on a bridge order it can carry a destination amount the provider recorded while the leg was still in flight. Kept as-is for existing integrators — prefer the explicit originReceivedAmount / destinationReceivedAmount pair.
